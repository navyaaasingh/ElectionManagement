# Election Management System — Complete Setup & Run Guide

### Execution Architecture: Infrastructure → Blockchain → Backend → ML → Frontend

> Run every command in order for a smooth deployment experience.  
> All commands assume macOS and the terminal app (zsh/bash).

---

## PART 0 — Prerequisites & Tools

Skip any tool you already have installed (check with `--version`).

### 0.1 · Node.js (v20+) & Python (3.11+)

1. Ensure [Docker Desktop](https://www.docker.com/products/docker-desktop/) is running.

## PART 10 — ESP32 Terminal Connection (WiFi → MQTT → Backend → Vote Ack)

This section is the end-to-end checklist for bringing up the ESP32 voting terminal from network setup to successful MQTT round-trips.

### 10.1 · Required Services Before Flashing

Start infra first:
```bash
docker compose up -d postgres mongodb redis mqtt-broker zookeeper kafka ml-analytics
docker compose ps
```

Start backend in a separate terminal:
```bash
cd backend
npm install
npm run dev
```

Quick health checks:
```bash
curl http://localhost:3000/health
curl http://localhost:5001/health
```

### 10.2 · Create a 2.4 GHz WiFi Network for ESP32 (macOS)

ESP32 must join a 2.4 GHz SSID. If your SSID is 5 GHz only, terminal will fail with `NO_AP_FOUND`.

Option A: Phone hotspot (fastest)
1. Enable hotspot with a 2.4 GHz-compatible mode.
2. Set SSID and password.
3. Keep phone near ESP32 during boot.

Option B: macOS Internet Sharing
1. Open System Settings → General → Sharing.
2. Turn on Internet Sharing.
3. Set Share your connection from to your upstream interface.
4. Set To computers using to Wi-Fi.
5. Open Wi-Fi Options and set:
	- Network Name (SSID): your ESP32 SSID
	- Security: WPA2/WPA3 Personal
	- Password: your ESP32 password
6. Save and confirm sharing is ON.

Find your Mac LAN IP (this will be MQTT server host):
```bash
ipconfig getifaddr en0 || ipconfig getifaddr en1
```

### 10.3 · Configure ESP32 Firmware

Edit `iot-terminal/firmware/config.h` and set these fields:
- `WIFI_SSID` and `WIFI_PASSWORD`
- `MQTT_SERVER` to the host LAN IP found above (example: `192.168.1.6`)
- `MQTT_PORT` (default `1883`)
- `MQTT_USERNAME` and `MQTT_PASSWORD` (optional for current local Mosquitto config)
- `TERMINAL_ID` and `DISTRICT_ID`

Important local defaults currently in repo:
- MQTT topic for auth request: `election/auth/request`
- MQTT topic for vote submit: `election/vote/submit`
- Auth response topic format: `election/auth/response/<TERMINAL_ID>`
- Vote ack topic format: `election/vote/ack/<TERMINAL_ID>`

### 10.4 · Build, Flash, and Monitor

```bash
cd iot-terminal
platformio run
platformio run --target upload
platformio device monitor --baud 115200
```

If auto-port fails, set explicit upload port:
```bash
platformio run --target upload --upload-port /dev/cu.usbserial-0001
platformio device monitor --port /dev/cu.usbserial-0001 --baud 115200
```

### 10.5 · Validate End-to-End Messaging

In another terminal, tail MQTT traffic:
```bash
docker exec -it election-mqtt mosquitto_sub -t 'election/#' -v
```

Expected serial milestones on ESP32:
1. `WiFi connected` and local IP printed.
2. `MQTT connected` and subscriptions confirmed.
3. On finger scan, auth publish to `election/auth/request`.
4. Backend sends auth response to `election/auth/response/<TERMINAL_ID>`.
5. Vote publish to `election/vote/submit`.
6. Backend vote ack to `election/vote/ack/<TERMINAL_ID>`.

Backend should log MQTT connection and IoT service startup.

### 10.6 · Backend Data Preconditions for Successful ESP32 Auth

Auth will fail unless all of these are true:
1. Voter exists with `status='active'` and `has_voted=false`.
2. `voters.biometric_hash` exactly matches ESP32-captured SHA-256 hash.
3. At least one election has `status='ACTIVE'`.
4. Active candidates for that election are at most 4 (button mode limit).

Useful SQL checks:
```bash
docker exec -it election-postgres psql -U election_admin -d election_db
```

```sql
SELECT voter_id, status, has_voted, biometric_hash FROM voters;
SELECT election_id, status FROM elections ORDER BY created_at DESC;
SELECT election_id, COUNT(*) AS active_candidates
FROM candidates
WHERE status = 'active'
GROUP BY election_id;
```

### 10.7 · ESP32 Troubleshooting Matrix

1. Symptom: `NO_AP_FOUND`
	Cause: SSID mismatch, weak signal, or 5 GHz-only network.
	Fix: use 2.4 GHz SSID, verify credentials in `config.h`, move device closer.

2. Symptom: `WiFi connection timeout`
	Cause: wrong password or AP unavailable.
	Fix: recheck SSID/password, restart hotspot/router, then reboot ESP32.

3. Symptom: `MQTT connection failed, rc=-2`
	Cause: wrong `MQTT_SERVER`, broker down, or network route failure.
	Fix: verify host IP in `config.h`, confirm `election-mqtt` container healthy, ensure port 1883 reachable.

4. Symptom: Auth rejected (`Biometric not recognized` / `Invalid biometric hash format`)
	Cause: hash mismatch or non-64-char hash.
	Fix: use the exact 64-char hash printed by ESP32 and store it in `voters.biometric_hash`; set voter `status` to `active`.

5. Symptom: Auth rejected (`No active election`)
	Cause: no election with `status='ACTIVE'`.
	Fix: activate/create election in DB.

6. Symptom: Auth rejected (`Button mode supports up to 4 active candidates`)
	Cause: active candidate count > 4 for election.
	Fix: reduce active candidate count to 4 or fewer.

7. Symptom: Vote ack timeout
	Cause: backend did not ack in time.
	Fix: verify backend logs and MQTT topics; terminal will cache vote for retry if transport fails.

8. Symptom: Serial upload/monitor port not found
	Cause: incorrect serial device or cable/driver issue.
	Fix: reconnect USB, check `/dev/cu.usbserial*`, set explicit `--upload-port` and `--port`.
